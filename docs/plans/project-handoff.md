# ATS Project Handoff

Last updated: 2026-10-01

다음 작업을 시작할 때 먼저 읽는 요약과 점검표입니다. 아래 상태는 마지막 확인 시점의
기록이며 현재 클라우드 상태나 새로운 실행 승인을 대신하지 않습니다.
세부 구현 근거는 [현재 상태](status.md), 승인 범위는 [전체 계획](ats-master-plan.md)과
[실거래 확장 계획](live-autotrading-plan.md)을 기준으로 확인합니다.

## Start Here

1. 이 문서와 [현재 상태](status.md)를 읽고 최신 사용자 요청과 남은 작업을 대조합니다.
   아키텍처·범위 변경 전에는 전체 계획을, 주문 관련 변경 전에는 실거래 확장 계획도 읽습니다.
2. 작업 트리와 관련 파일의 현재 내용을 확인합니다. `git status --short`로 사용자 변경을
   파악하고 기존 변경을 되돌리거나 기존 산출물을 덮어쓰지 않습니다.
3. 아래 배포·검증 기록의 날짜를 확인합니다. Azure 작업이 필요할 때만 명시적 구독으로
   현재 리소스·인증 설정·자격증명 만료 메타데이터를 읽기 전용으로 재확인합니다.
   로컬 작업을 시작한다는 이유로 클라우드를 변경하거나 비밀값을 조회하지 않습니다.
4. 이번 작업의 목표와 가장 작은 검증 방법을 정합니다. 지속 수집·저장, 권한 변경,
   비밀 교체, 배포 범위 확대 및 실거래 활성화에 과거의 다른 승인을 재사용하지 않습니다.
5. 실제 데이터·증권사·주문 연결이 필요한지 구분합니다. 승인되지 않은 외부 호출이나
   실주문을 테스트 대용으로 실행하지 않고, 단위 테스트는 고정된 오프라인 입력을 사용합니다.
6. 변경 범위에 맞는 테스트·린트·타입 또는 문서 검사를 실행합니다. 문서만 변경했다면
   불필요한 전체 테스트나 재배포 대신 문서 진단과 링크를 검사합니다.
7. 수행한 작업과 관측한 결과만 기록합니다. 상태가 바뀌면 이 문서와 관련 상태 문서를
   갱신하고, 미검증·차단·승인 예외를 완료와 구분합니다.

**금지할 재시작 동작:** 인프라 생성 스크립트의 `-Execute`를 습관적으로 재실행하거나,
자격증명을 자동 재발급하거나, 전략·위험 정책·실거래를 자동 활성화하지 않습니다.
키·토큰·비밀번호를 채팅, 소스, 명령 인수, 로그에 넣지 않습니다.

## Objective and Boundaries

최종 목표는 한국 주식·ETF의 데이터를 수집·분석하고, 전략 후보를 연구·검증한 뒤,
사람이 승인한 운영 전략으로 허용된 주문을 자동 실행하는 ATS입니다.

`데이터 수집 -> 시점·품질 검증 -> 후보 연구 -> 백테스트·모의투자 -> 사람 승인 -> 독립 위험 검사 -> 주문·대사 -> 다음 연구`

- 운영 전략은 불변 버전입니다. 개선 후보는 별도로 만들며 승격·롤백은 사람이 승인합니다.
- 연구 AI는 증권사 비밀, 주문 권한, 위험 정책을 변경할 권한을 갖지 않습니다.
- 후속 실거래 개발 목표는 적격성이 확인된 국내 일반 주식·일반 ETF, 현금만 사용하는
  매수와 실제 보유 범위의 매도, 장 마감 분석 및 다음 거래일의 승인된 시간대 주문입니다.
- 종목별 10%, 일일 손실 1% 중단, 최대 낙폭 15% 중단 기준을 유지합니다.
  별도 고정 투자금·일일 누적 매수액·주문 건수 상한은 추가하지 않는 요구사항입니다.
  현금·비용·예약·노출·중복·손실 검사는 여전히 적용되며 손실 상한을 보장하지 않습니다.
- 신용·레버리지·공매도·파생상품·레버리지/인버스 상품·장중 전략은 범위 밖입니다.
- **실거래 개발 확장 승인과 실제 계좌의 활성화 승인은 다릅니다. 현재 실거래는 미승인입니다.**
  기존 paper-only 계약과 과거 전략·스냅샷을 새 범위로 재해석하지 않습니다.

## Implemented So Far

| 영역 | 구현·확인한 내용 | 아직 의미하지 않는 것 |
| --- | --- | --- |
| 개발 기반 | Python 3.11, uv, 고정 의존성, Ruff·Pyright·pytest·스키마 검사 | 실제 운영 통합 완료 |
| 전략 계약 | 불변 전략 버전·부모 계보·해시·제한된 후보 변경·승인 기록 계약 | 영속 레지스트리나 인증된 승인 서비스 |
| 데이터 기반 | 시점 기준 선택, 수정 이력, 출처 권리·해시·과거 투자 대상 검증, 로컬 입력 재생 | 지속 수집·실제 데이터 저장소 |
| KIS 조회 | 운영 시세 전용 클라이언트, 오프라인 일별 가격 정규화, 사용자 단발 조회 성공 기록 | 계좌·주문 연결, 일반 수집 승인, 원문이 보존된 데이터셋 |
| 연구 데모 | 합성 단일 종목 추세 백테스트, 비용·슬리피지, 후보 3개 비교 | 실제 Qlib·LEAN 검증이나 투자 성과 인증 |
| 위험 검사 | 수치 기반 주문 검사와 긴급 중단 시나리오 | 실제 계좌 상태·자금 예약·주문 제출 통합 |
| 대시보드 | 한국어 차트, 후보 비교, 거래 필터, 위험 검사 표시, 로컬 CSV 미리보기 | 실시간 시세·AI 연구·자동 주문을 수행하는 운영 화면 |
| Azure | 본인 전용 합성 보고서의 정적 미리보기 게시 | 전체 ATS 백엔드 배포 |
| GitHub Actions | main push 실행에서 양 OS 품질 검사·OIDC·합성 게시 성공 확인 | 별도 PR·수동 실행·실제 장애 복구의 원격 시험은 미수행 |

KIS 단발 조회의 원문은 저장하지 않았고 데이터 완전성은 미검증입니다. 기본 운영 정책은
DRAFT이며, 별도 조회 허용을 반복 수집·저장·재배포 허용으로 확대하지 않습니다.
현재 Azure 화면은 이미 생성된 합성 보고서입니다. CI/CD 파일을 main에 반영했고,
품질 검사를 통과한 합성 산출물의 첫 자동 게시 실행까지 확인했습니다. 실시간 시세 화면은 아닙니다.

## Remaining Work

1. **실제 데이터:** 반복 수집·저장 범위와 보존 정책 승인, 거래 달력·기업행동·수정 이력·
   상장폐지·과거 투자 대상 처리, 재현 가능한 실제 데이터셋 구축.
2. **연구·검증 엔진:** 실제 Qlib·LEAN 연결, 다종목·포트폴리오 평가, 표본 외 검증,
   비용·유동성 스트레스 및 엔진 간 비교 기준 확정.
3. **주문·위험 통제:** 인증된 계좌·잔고·보유 상태, 영속 주문 장부, 원자적 자금 예약,
   단일 주문 실행 주체, 중복 방지, 미확정 주문 조회·부분 체결·장애 복구.
4. **모의투자:** KIS 모의주문 연결, 장애·중단·재시작 검사, 최소 20개 실제 모의운영 세션.
5. **AI 개선 루프:** 격리된 연구 실행, 계산·시간 예산, 영속 후보 등록, 평가·승인·롤백 연결.
6. **운영 서비스:** 스케줄러, 운영 API, 인증된 승인·중단 화면, 감사 기록, 경보·모니터링.
7. **배포 자동화:** 첫 실제 main push의 OIDC·게시 성공을 확인했습니다. 향후 액션 런타임
   업데이트와 PR·수동 실행·장애 복구 시험은 별도 후속 검토 대상으로 남깁니다.
8. **실거래:** 별도 어댑터와 계좌·전략·운영 범위를 확정하고 기존 검증·모의운영을 마친 뒤
   명시적인 첫 활성화 승인을 받습니다. 거래마다 확인하지 않는 목표는 승인된 범위 안에서만 적용합니다.

최신 우선순위는 **GitHub Actions 자동 배포**입니다. 사용자는 나머지 ATS 작업을 직접
검토한 뒤 진행하기로 했으므로 데이터 수집·주문·연구 개발로 자동 확장하지 않습니다.
CI/CD 첫 원격 검증은 완료했습니다. [자동 배포 안내](../../infra/github-actions.md)의 실제 실행
근거와 후속 항목을 먼저 확인하고 완료한 검증·인프라 생성을 반복하지 않습니다.
추가 커밋·푸시와 새 실행은 별도 사용자 요청 없이 수행하지 않습니다.
향후 ATS 개발을 재개하면 실제 데이터의 반복 수집·저장 범위 확정과 데이터셋 구축이 우선입니다.

## Evidence and Maintenance

- [현재 상태](status.md): 상세 구현 근거와 과거 단계별 기록. 오래된 미완료 문구는 기록 시점을 구분합니다.
- [전체 계획](ats-master-plan.md), [실거래 확장](live-autotrading-plan.md): 승인 범위와 불변 조건.
- [운영 준비 조건](predeployment.md): 전체 ATS의 미완료 조건. 미리보기 게시와 혼동하지 않습니다.
- [KIS 데이터 안내](../sources/kis-market-data.md): 단발 조회 근거와 이용·보존 범위.
- [품질 워크플로](../../.github/workflows/quality.yml): 현재 push·PR 검증 구성.
- 같은 로컬 환경에서는 `.copilot-azure/sessions/active-session.json`이 가리키는 세션의
  `deploy-result.json`, `deployment-summary.md`, `deploy-audit.log`로 배포 근거를 확인합니다.
  `.copilot-azure/`와 `.local/`은 Git 제외 경로이므로 다른 환경에 없을 수 있습니다.
  없다는 이유로 리소스·앱 등록·비밀을 다시 만들지 않습니다.
- 테스트 수치는 특정 시점·범위의 결과입니다. 과거 전체 검사 결과나 일부 검사를 합산해
  현재 전체 테스트가 통과했다고 표현하지 않습니다.
- 이 문서에 비밀값·토큰·계좌번호를 추가하지 않습니다. 변경이 생기면 날짜와 실제 근거,
  남은 작업을 갱신하되 과거 승인·검증 기록을 성공한 것처럼 다시 쓰지 않습니다.
